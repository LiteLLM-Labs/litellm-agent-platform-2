Implementation plan

Managed Agent Runtime Flow

Browser-facing endpoint map for starting a managed-agent runtime session, storing runtime credentials, landing on chat, and routing messages through the shared runtime contract. Examples use placeholders only; API keys are never rendered back to the browser except as masked status.

Happy Path

1. Open Start Session

Load selectable agents and runtimes

The page asks for DB-backed managed agents and runtime connection status before enabling the Start session button.

GET /api/agents
GET /api/agent-runtimes
2. Save Credentials

Store runtime secret server-side

Runtime API keys are encrypted in the credentials table. The UI receives connection metadata and a masked key, not the secret.

PUT /api/agent-runtimes/{runtime}/credentials
3. Start Session

Create local session, then provision provider runtime

LAP owns the local session row, credential lookup, idempotency refs, and provider IDs. Provider-specific launch logic stays behind the runtime adapter.

POST /session
4. Land On Chat

Hydrate transcript and subscribe to events

Chat loads the session metadata and stored messages, then opens the event stream used by the local UI renderer.

GET /session/{id}
GET /session/{id}/message
GET /event
5. Send / Invoke

Normalize user input into runtime events

The planned managed-runtime path converts composer text into the SDK event contract and forwards it to the provider session.

POST /session/{id}/prompt_async
POST /v1/sessions/{provider_session_id}/events

Unified SDK Contract

Create

LAP maps the selected managed agent into provider runtime calls. The shared abstraction returns RuntimeProvision: runtime agent ID, provider session/run IDs, optional provider URL, and provider metadata. 

RuntimeSessionInput {
  session_id,
  prompt,
  environment
}
Send

Chat composer text should become the provider-neutral event shape. For Claude Agents this is the Anthropic Managed Agents events API. 

POST /v1/sessions/{id}/events
{
  "events": [{
    "type": "user.message",
    "content": [{ "type": "text", "text": "..." }]
  }]
}
Stream

Runtime SSE is normalized back into the UI's message and tool event model: agent.message, agent.tool_use, agent.tool_result, session.status_idle, and session.error. 

GET /v1/sessions/{id}/events/stream

Runtime Divergence

Concern Cursor Claude Agents
Runtime ID cursor claude_agents
Default API base https://api.cursor.com https://api.anthropic.com
Required start-session environment Requires repo source data: repository, optional ref, target branch template, and optional PR flag. Does not require repo fields in the current UI. Environment is created by the provider adapter with cloud networking defaults.
Provider launch calls POST /v0/agents with prompt, source, model, and target. POST /v1/agents, then POST /v1/environments, then POST /v1/sessions with Managed Agents beta headers.
Remote IDs stored locally Provider agent/run ID is stored as provider_run_id; provider_session_id is usually empty. Provider session ID is stored as provider_session_id; run ID is usually empty.
Message invocation plan Needs a Cursor event/run continuation adapter before chat sends can be fully provider-backed. Uses the SDK event contract: /v1/sessions/{id}/events and /v1/sessions/{id}/events/stream.

Implementation Notes

Security boundary

Browser requests authenticate to LAP with the master-key flow. Runtime API keys are submitted once, encrypted server-side, and only returned as masked status. Do not place provider keys in query strings, localStorage, server logs, or this artifact.

Current gap to close

The current chat UI posts composer text to /session/{id}/prompt_async. For runtime sessions, that handler should branch on stored runtime and provider_session_id / provider_run_id, then call the unified SDK send/stream path instead of launching a local sandbox harness.
